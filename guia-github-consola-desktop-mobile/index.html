📘 Guía práctica para estudiantes

Trabajo colaborativo en GitHub: ramas, archivos y Pull Request

En esta guía aprenderás a agregar colaboradores a un proyecto de GitHub y a trabajar en equipo usando tres formas: consola / Git Bash, GitHub Desktop y GitHub Mobile. Cada estudiante debe crear su propia rama, subir un archivo y enviar un Pull Request para que el dueño del repositorio lo revise.

1

Objetivo de la práctica

Que los estudiantes aprendan el flujo básico de colaboración en GitHub: ser agregados como colaboradores, crear una rama propia, realizar cambios sin afectar la rama principal, subir sus archivos y solicitar revisión por medio de un Pull Request.

Resultado esperado: al finalizar, cada estudiante tendrá una rama con su nombre, un archivo agregado al repositorio y un Pull Request creado correctamente.
2

Flujo general de trabajo

  1. El dueño crea el repositorio y agrega a sus compañeros como colaboradores.
  2. Cada colaborador clona el repositorio o lo abre desde GitHub Desktop.
  3. Cada estudiante crea una rama con su nombre o tarea.
  4. El estudiante agrega o modifica un archivo.
  5. Realiza commit y sube la rama a GitHub.
  6. Crea un Pull Request para solicitar que sus cambios sean revisados.
  7. El dueño o revisor revisa, comenta, solicita cambios o aprueba.
3

Agregar colaboradores

Este paso lo realiza el dueño del repositorio.

1
Entrar a GitHub y abrir el repositorio del proyecto.
2
Entrar a Settings.
3
Buscar la opción Collaborators o Collaborators and teams.
4
Presionar Add people y escribir el usuario o correo de GitHub del compañero.
5
El colaborador debe aceptar la invitación desde su correo o notificación de GitHub.

Roles recomendados

  • Dueño: crea el repositorio, invita colaboradores y revisa Pull Requests.
  • Colaborador: crea una rama, sube su archivo y solicita revisión.
  • Revisor: comenta, aprueba o solicita correcciones.
4

Opción A: hacerlo desde consola o Git Bash

Esta opción es ideal para que los estudiantes practiquen comandos básicos de Git.

Comandos paso a paso

1. Clonar el repositorio

git clone URL_DEL_REPOSITORIO
cd nombre-del-repositorio

2. Crear una rama propia

git checkout -b nombre-estudiante

Ejemplo:

git checkout -b ana-presentacion

3. Crear o copiar el archivo

echo "Hola, soy Ana y este es mi aporte" > ana.html

4. Verificar cambios

git status

5. Agregar y guardar cambios

git add .
git commit -m "Agrego archivo de Ana"

6. Subir la rama a GitHub

git push -u origin ana-presentacion
Importante: no trabajar directamente en main o master. Cada estudiante debe trabajar en su propia rama para evitar conflictos.
5

Opción B: hacerlo desde GitHub Desktop

GitHub Desktop permite trabajar con Git de forma visual, sin escribir tantos comandos.

Pasos desde GitHub Desktop

1
Instalar GitHub Desktop e iniciar sesión con la cuenta de GitHub.
2
Ir a File → Clone repository y seleccionar el repositorio compartido.
3
Presionar Current Branch y luego New Branch.
4
Escribir el nombre de la rama, por ejemplo: maria-aporte.
5
Agregar el archivo en la carpeta del proyecto desde el explorador de archivos.
6
Volver a GitHub Desktop, escribir un resumen del cambio y presionar Commit to rama.
7
Presionar Publish branch para subir la rama a GitHub.
8
Presionar Create Pull Request para solicitar revisión.
6

Opción C: usar GitHub Mobile

GitHub Mobile es útil para trabajar desde el celular, especialmente para revisar Pull Requests, recibir notificaciones, comentar cambios, aprobar revisiones y hacer correcciones pequeñas.

Recomendación para clase: usar GitHub Mobile como apoyo para revisión y seguimiento. Para subir muchos archivos o trabajar con carpetas completas, es más cómodo usar consola o GitHub Desktop.

Instalación y acceso

1
Instalar la app oficial GitHub Mobile desde App Store o Google Play.
2
Iniciar sesión con la cuenta de GitHub.
3
Buscar el repositorio del proyecto desde la pestaña de búsqueda o perfil.
4
Activar notificaciones del repositorio con Watch para recibir avisos de Pull Requests.

Crear Pull Request desde GitHub Mobile

Cuando la rama ya fue subida desde consola o GitHub Desktop, también se puede crear el Pull Request desde el celular.

1
Abrir el repositorio en GitHub Mobile.
2
Tocar el botón + desde la vista del repositorio o Pull Requests.
3
Seleccionar la rama que contiene los cambios.
4
Revisar los archivos modificados antes de enviarlo.
5
Escribir título y descripción clara, por ejemplo: Agrego archivo de María.
6
Crear el Pull Request para que el dueño del repositorio lo revise.

Revisar y comentar desde GitHub Mobile

1
Entrar a Pull Requests.
2
Abrir el Pull Request de un compañero.
3
Leer la descripción y revisar los archivos cambiados.
4
Escribir un comentario si hay algo que corregir.
5
Si tienes permiso, aprobar, solicitar cambios o unir el Pull Request.

Trabajo desde celular usando navegador

Si un estudiante no tiene computadora, puede intentar trabajar desde el navegador del celular entrando a github.com. En algunos celulares conviene activar sitio de escritorio para ver mejor las opciones de ramas, edición de archivos y creación del Pull Request.

Advertencia: para proyectos con varios archivos, carpetas o imágenes pesadas, el celular puede ser incómodo. Lo más recomendable es que GitHub Mobile sea usado para revisar, comentar y crear Pull Requests desde ramas ya subidas.
7

Crear el Pull Request

El Pull Request es la solicitud para que los cambios de una rama se revisen antes de unirlos a la rama principal.

ElementoQué debe colocar el estudianteEjemplo
Base branchRama principal donde se unirán los cambiosmain
Compare branchRama del estudianteana-presentacion
TítuloResumen breve del trabajo realizadoAgrego archivo de Ana
DescripciónExplicación de lo que se agregóSubí mi archivo HTML con mi aporte al proyecto.
RevisorDueño del repositorio o docenteProfesor / coordinador del equipo

Descripción sugerida para el Pull Request

## Descripción
Agregué mi archivo personal al proyecto.

## Cambios realizados
- Creé mi rama de trabajo.
- Agregué el archivo ana.html.
- Subí los cambios al repositorio.

## Solicitud
Solicito revisión para unir mis cambios a la rama main.
8

Actividad práctica para estudiantes

Modalidad: trabajo grupal de 4 a 5 estudiantes.

Producto final: repositorio en GitHub con un archivo por estudiante y Pull Requests revisados.

  1. Un estudiante crea el repositorio llamado practica-github-equipo.
  2. El dueño agrega a sus compañeros como colaboradores.
  3. Cada colaborador crea una rama con su nombre.
  4. Cada estudiante crea un archivo con su nombre, por ejemplo: maria.html, juan.html.
  5. Dentro del archivo debe escribir una pequeña presentación personal y el rol que tuvo en el equipo.
  6. Cada estudiante debe hacer commit y subir su rama.
  7. Cada estudiante debe crear un Pull Request.
  8. El dueño o revisor debe comentar o aprobar cada Pull Request.
  9. Al final, deben unir los Pull Requests a main.

Archivo de ejemplo

<!DOCTYPE html>
<html lang="es">
<head>
  <meta charset="UTF-8">
  <title>Aporte de Ana</title>
</head>
<body>
  <h1>Hola, soy Ana</h1>
  <p>Mi aporte fue crear mi rama y subir este archivo.</p>
</body>
</html>

Lista de cotejo

  • El estudiante aceptó la invitación como colaborador.
  • Creó una rama con nombre claro.
  • Agregó su archivo correctamente.
  • Realizó commit con mensaje descriptivo.
  • Subió su rama a GitHub.
  • Creó el Pull Request.
  • Participó en revisión o comentario de un PR.
  • Usó GitHub Mobile para revisar, comentar o dar seguimiento.

Creación de rama2 ptsCrea una rama propia con nombre claro y no trabaja directamente en main.
Archivo agregado2 ptsAgrega un archivo con contenido correcto y relacionado con la actividad.
Commit y push2 ptsRealiza commit con mensaje claro y sube correctamente la rama.
Pull Request y revisión2 ptsCrea el Pull Request y participa en revisión, comentario o seguimiento desde web, Desktop o Mobile.

Error: estoy en main

Crea una rama antes de modificar archivos:

git checkout -b mi-rama

Error: no puedo subir

Verifica que aceptaste la invitación como colaborador y que tienes permiso de escritura.

Error: hay conflictos

Actualiza tu rama con la principal y revisa los archivos marcados como conflicto antes de hacer commit.
